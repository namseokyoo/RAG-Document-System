refactor: Settings save only updates config, no reconnect

## Change

**Before**: Settings save attempted reconnect and UI update
- Slow when network drive not connected
- Confusing UX (saves multiple settings at once)

**After**: Settings save only writes to config.json
- Fast and predictable
- User controls when to reconnect via menu

## Workflow

### 1. Settings Tab - Save Button
- **Action**: Write to config.json only
- **No reconnect, no UI update**
- **Message**: If shared DB changed, suggest using menu reconnect

### 2. Menu - "공용DB 재접속"
- **Action**: Read config.json → Reconnect → Update UI
- **This is the only way to activate/deactivate shared DB UI**

### 3. Program Start
- **Action**: Read config.json → Check DB file → Set initial UI state

## Benefits

- Settings save is always fast
- No unexpected delays from network drives
- Clear separation: settings vs. connection
- User controls when to connect (menu action)
