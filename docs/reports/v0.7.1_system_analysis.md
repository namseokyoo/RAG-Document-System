## 📊 시스템 개요

### 아키텍처

본 시스템은 **2개의 독립적인 파이프라인**으로 구성됩니다:

1. **Pipeline A: 문서 인제스션 (Document Ingestion)**
   - 문서 업로드 → 청킹 → 비전 처리 → 임베딩 → 저장
   - PDF, PPTX, XLSX, TXT 지원
   - Vision-Augmented 청킹 (PPTX/PDF)

2. **Pipeline B: 질의응답 (Question Answering)**
   - 사용자 질문 → 검색 → 재순위 → 답변 생성 → Citation
   - 12단계 고급 검색 파이프라인
   - Multi-Query, HyDE, Query Decomposition 지원

## 🔄 Pipeline A: 문서 인제스션 분석

### 주요 컴포넌트

1. **DocumentProcessor** (`utils/document_processor.py`)
   - 파일 타입 감지 및 라우팅
   - 구조 인식 청킹 엔진 연동
   - Vision 처리 통합

2. **PDFChunkingEngine** (`utils/pdf_chunking_engine.py`)
   - Small-to-Large 아키텍처
   - Layout-Aware 분석 (폰트, 좌표, 계층 구조)
   - Vision-Augmented 청킹 (Hybrid 모드)
   - 표 다층 청킹 (전체/행/열/키-값)
   - Poppler 기반 PDF → 이미지 변환

3. **PPTXChunkingEngine** (`utils/pptx_chunking_engine.py`)
   - Small-to-Large 아키텍처
   - paragraph.level 기반 불릿 그룹핑
   - Vision-Augmented 청킹 (Windows COM 렌더링)
   - 표 다층 청킹
   - PPTX → PDF 자동 변환 (v0.6.0+)

4. **VectorStoreManager** (`utils/vector_store.py`)
   - ChromaDB 관리 (로컬/공유 DB)
   - 임베딩 생성 및 저장
   - BM25 인덱스 관리

### 최근 개선사항 (v0.6.0 → v0.7.1)

#### 1. PPTX → PDF 자동 변환 (v0.6.0)
- **구현**: Windows COM을 통한 PowerPoint 자동 변환
- **효과**: PPTX 파일도 PDF 파이프라인 활용 가능
- **설정**: `auto_convert_pptx_to_pdf`, `pptx_conversion_tool`

#### 2. PDF 임베딩 시간 감지 로직 개선 (v0.6.1)
- **문제**: 평균 처리 시간의 3배 초과 시 강제 중단
- **해결**: 상대값 체크를 경고로 변경, 절대 타임아웃(120초)만 강제
- **효과**: Vision API 지연 시에도 처리 계속 진행

#### 3. Vision API 타입별 Base URL 제어 (v0.6.0)
- **구현**: Vision API 타입별 엔드포인트 분리
- **효과**: OpenAI/OpenAI-compatible 호환성 향상

## 🔄 Pipeline B: 질의응답 분석

### 12단계 검색 파이프라인

```
1. 질문 분류 (Question Classifier)
   ↓
2. 파일 멘션 검출 (@filename)
   ↓
3. Intent Detection (파일명 명시)
   ↓
4. Session Context (최근 업로드 문서)
   ↓
5. Query Expansion (Multi-Query, HyDE, Query Decomposition)
   ↓
6. Hybrid Search (Vector + BM25)
   ↓
7. Small-to-Large Context 확장
   ↓
8. 중복 제거 (chunk_id 기반)
   ↓
9. Cross-Encoder Re-ranker
   ↓
10. Score-based Filtering (Adaptive Threshold)
   ↓
11. Diversity Penalty 적용
   ↓
12. 최종 컨텍스트 구성
```

### 주요 컴포넌트

1. **RAGChain** (`utils/rag_chain.py`)
   - 전체 검색 파이프라인 오케스트레이션
   - Multi-Query 병렬 처리 (ThreadPoolExecutor)
   - Session Context + Intent Detection 통합

2. **HybridRetriever** (`utils/hybrid_retriever.py`)
   - Vector Search (ChromaDB)
   - BM25 Keyword Search (rank-bm25)
   - 가중치 합산 (기본 0.5:0.5)

3. **Reranker** (`utils/reranker.py`)
   - Cross-Encoder 기반 (`multilingual-mini`)
   - 점수 정규화 (0-100 범위)
   - Singleton 패턴 (인스턴스 재사용)

4. **QuestionClassifier** (`utils/question_classifier.py`)
   - 규칙 기반 + LLM 하이브리드 분류
   - 4가지 유형: simple/normal/complex/exhaustive

5. **SessionContext** (`utils/session_context.py`)
   - 5분 타임아웃 기반 세션 관리
   - 최근 업로드 문서 추적

6. **IntentDetector** (`utils/intent_detector.py`)
   - 한국어/영어 문서 참조 패턴 감지
   - 지시대명사, 시간 기반 참조 감지

### 최근 개선사항 (v0.6.0 → v0.7.1)

#### 1. 성능 최적화 Quick Wins (v0.6.0)
- **BM25 가중치 동적 조정**: 질문 유형별 최적화
  - Simple: 0.7/0.3 (BM25/Vector)
  - Normal: 0.5/0.5
  - Complex: 0.3/0.7
  - Exhaustive: 0.5/0.5
- **Adaptive Threshold 최적화**: 질문 유형별 percentile 조정
  - Simple: 0.7
  - Normal: 0.6
  - Complex: 0.5
  - Exhaustive: 0.4
- **Gap-based Cutoff 활성화**: 점수 gap 기반 자동 컷오프

#### 2. Reranker 중복 호출 제거 (v0.4.6)
- **문제**: 각 쿼리마다 + 최종 통합에서 총 N+1번 호출
- **해결**: 최종 통합 후 한 번만 호출
- **효과**: 응답 시간 70-75% 단축, Reranker 호출 4회 → 1회

#### 3. 중복 제거 로직 개선 (v0.4.6)
- **문제**: 처음 50자만 비교 (버그)
- **해결**: chunk_id 우선 사용, 없으면 MD5 해시 사용
- **효과**: 데이터 무결성 완전 해결

#### 4. Multi-Query 병렬화 (v0.5.0+)
- **구현**: ThreadPoolExecutor를 통한 병렬 검색
- **효과**: 여러 쿼리 검색 시간 단축

## ⚙️ 설정 시스템

### ConfigManager (`config.py`)

**주요 설정 항목:**

1. **LLM 설정**
   - API 타입: ollama/openai/request
   - 모델, Base URL, API 키
   - Temperature (기본 0.3)

2. **임베딩 설정**
   - API 타입: ollama/request
   - 모델: mxbai-embed-large (기본)
   - Base URL, API 키

3. **검색 설정**
   - Multi-Query: 활성화 여부, 개수 (0-5)
   - HyDE: 활성화 여부
   - Query Decomposition: 활성화 여부
   - Hybrid Search: 활성화 여부, BM25 가중치

4. **Re-ranker 설정**
   - 사용 여부, 모델 (multilingual-mini)
   - Initial K (기본 30)

5. **Score Filtering 설정**
   - Adaptive Threshold: 활성화 여부, percentile
   - 최소/최대 문서 수 (3-20)

6. **Vision 설정**
   - Vision 청킹: 활성화 여부
   - API 타입, 모델, Base URL
   - PDF DPI, Detail 레벨

7. **공유 DB 설정**
   - 사용 여부, 경로
   - 드라이브 문자, 기본 검색 모드
