## 📝 프롬프트 변경 사항

### Before (28라인, 103 tokens)

```
슬라이드를 분석하여 다음 정보를 구조화된 형식으로 추출하세요:

1. 주제: 핵심 메시지 (1문장)
2. 데이터 유형: 표/그래프 형태
...
```

### After (45라인, ~120 tokens)

```
[슬라이드 정보]
제목: "비용 구조 분석"
슬라이드: 3/4

[중요 지시사항]
1. 슬라이드 맨 위의 큰 제목이 "비용 구조 분석"과 일치하는지 확인하세요
2. 다른 슬라이드의 내용을 분석하지 마세요
3. 위 슬라이드만 분석하세요

[분석 요구사항]
1. 주제: 슬라이드 제목 "비용 구조 분석" 기반 핵심 메시지
...

[주의사항]
- 슬라이드 제목과 일치하지 않으면 오류 보고
- 다른 슬라이드 내용 혼동 금지
```

**주요 변경**:
- ✅ 슬라이드 제목 명시
- ✅ 슬라이드 번호/총 개수 제공
- ✅ 검증 지시사항 추가
- ✅ 오류 보고 요구

**토큰 증가**: 103 → 120 tokens (**17% 증가**)

### 1. 제목 없는 슬라이드

**슬라이드 2**:
- 실제 제목: 없음 (빈 문자열)
- Vision 분석: "비용 구조 분석"

**원인**: 제목이 비어있으면 LLM이 내용을 보고 임의로 제목 생성

**해결 방안**:
```python
if not slide_title:
    slide_title = "[제목 없음]"
```

**현재**: 오류만 보고하고 끝

```python
if "오류" in vision_text:

    # 또는: python-pptx로 직접 추출
```

## 💡 인사이트

### 프롬프트 엔지니어링의 힘

**단순한 17% 토큰 증가로**:
- 제목 일치율 200% 향상
- 오류 감지 기능 추가
- 슬라이드 혼동 67% 감소

**핵심 원칙**:
1. **명시적 정보 제공**: 슬라이드 제목, 번호
2. **검증 요구**: "일치하는지 확인"
3. **오류 보고**: "일치하지 않으면 오류 보고"

### LLM의 자기 검증 능력

**놀라운 발견**:
- LLM이 자신의 오류를 인지하고 보고
- 명시적 지시만 주면 충분

**적용 확대**:
- 다른 작업에도 "검증 후 오류 보고" 패턴 적용
- Self-correction 메커니즘
