## 📊 현재 시스템 구성 분석

### 핵심 구성 요소

#### 1. LLM 설정
- **모델**: `gpt-5-mini` (config.json 기준, 실제로는 OpenAI API 사용)
- **Temperature**: 0.3 (일관성 우선)
- **예상 실제 모델**: GPT-4o-mini 또는 유사 모델

#### 2. 임베딩 설정
- **모델**: `mxbai-embed-large` (Ollama)
- **특징**: 다국어 지원, 1024차원 임베딩
- **벤치마크 비교**: 
  - LangChain: OpenAI Embedding
  - Cohere: embed-multilingual-v3.0
  - Upstage: solar-embedding-1-large

#### 3. 검색 파이프라인 (12단계)

**활성화된 고급 기능:**

1. ✅ **Multi-Query** (3개)
   - 효과: 재현율 15-25% 향상
   - 벤치마크 비교: LangChain, Cohere도 사용

2. ✅ **HyDE** (Hypothetical Document Embeddings)
   - 효과: 복잡한 질문 처리 정확도 향상
   - 벤치마크 비교: 일부 솔루션만 사용

3. ✅ **Query Decomposition**
   - 효과: 다단계 질문 분해 처리
   - 벤치마크 비교: 고급 기능

4. ✅ **Hybrid Search** (BM25 + Vector, 0.5:0.5)
   - 효과: 키워드 검색 + 의미 검색 결합
   - 벤치마크 비교: Alli, LangChain도 사용

5. ✅ **Reranker** (multilingual-mini)
   - 효과: 정밀도 20-30% 향상
   - 벤치마크 비교: 대부분 사용

6. ✅ **Small-to-Large Context**
   - 효과: 컨텍스트 확장으로 정확도 향상
   - 벤치마크 비교: 고급 기능

7. ✅ **Question Classifier**
   - 효과: 질문 유형별 최적 파라미터 자동 조정
   - 벤치마크 비교: 고급 기능 (Alli만 사용 가능성)

8. ✅ **Adaptive Threshold**
   - 효과: 질문별 동적 필터링
   - 벤치마크 비교: 고급 기능

9. ✅ **Diversity Penalty** (0.3)
   - 효과: 다문서 합성 개선
   - 벤치마크 비교: 고급 기능

10. ✅ **Vision-Augmented 청킹**
    - 효과: 표/차트/이미지 처리
    - 벤치마크 비교: 고급 기능

## 🎯 성능 예측 분석

### 강점 요인 (성능 향상 기여도)

1. **Multi-Query (3개)** → +0.05~0.08
   - 여러 쿼리로 재현율 향상
   - 벤치마크: LangChain (0.610)도 사용

2. **Hybrid Search (BM25 + Vector)** → +0.03~0.05
   - 키워드 검색 강화
   - 벤치마크: Alli, LangChain도 사용

3. **Reranker (multilingual-mini)** → +0.04~0.06
   - 정밀도 향상
   - 벤치마크: 대부분 사용

4. **Question Classifier + Adaptive Threshold** → +0.02~0.04
   - 질문 유형별 최적화
   - 벤치마크: 고급 기능 (Alli만 가능성)

5. **HyDE + Query Decomposition** → +0.02~0.03
   - 복잡한 질문 처리
   - 벤치마크: 고급 기능

6. **Small-to-Large Context** → +0.01~0.02
   - 컨텍스트 확장
   - 벤치마크: 고급 기능

7. **Vision-Augmented 청킹** → +0.01~0.02
   - 표/차트 처리 (도메인별 차이)
   - 벤치마크: 고급 기능

**총 강점 기여도**: +0.19~0.32

### 약점 요인 (성능 저하 가능성)

1. **LLM 모델 불확실성** → -0.02~-0.05
   - "gpt-5-mini" 모델명 이상 (실제 모델 확인 필요)
   - GPT-4o-mini면 성능 양호, 더 약한 모델이면 저하

2. **임베딩 모델** → -0.01~-0.03
   - mxbai-embed-large는 좋지만, OpenAI Embedding과 비교 시 약간 낮을 수 있음

3. **문서 준비 상태** → -0.05~-0.15
   - **가장 큰 변수**: 평가 데이터셋의 문서가 실제로 업로드되어 있는지 불확실
   - 문서가 없으면 성능 급락

4. **프롬프트 최적화** → -0.01~-0.02
   - 벤치마크 솔루션들은 프롬프트 최적화 완료
   - 현재 시스템도 최적화되어 있지만 추가 개선 여지

**총 약점 기여도**: -0.09~-0.25 (문서 준비 상태에 따라 크게 변동)
