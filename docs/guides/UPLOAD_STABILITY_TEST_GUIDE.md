# 업로드 안정성 개선 - 실제 테스트 가이드

## 📋 구현 완료 사항
- ✅ 타임아웃 튜플 변경: `timeout=(10, 60)`
- ✅ 예외 클래스 정의: `CancelledException`, `PartialUploadException`
- ✅ 콜백 메커니즘: `cancel_callback`, `progress_callback`
- ✅ 재시도 로직: MAX_RETRIES=3, exponential backoff
- ✅ 취소 메커니즘: 각 페이지 처리 전/재시도 중 취소 체크
- ✅ 전체 롤백 전략: 부분 업로드 시 전체 취소

---

## 🧪 테스트 시나리오

### **시나리오 1: 정상 업로드 (기본 동작 확인)**

**목적**: 개선된 코드가 정상 업로드에 영향을 주지 않는지 확인

**준비물**:
- 12페이지 PDF 파일 (또는 다른 페이지 수의 PDF)

**테스트 절차**:
1. 데스크톱 앱 실행
2. "문서 업로드" 탭 선택
3. PDF 파일 업로드
4. 콘솔 출력 관찰

**예상 결과**:
```
[PDFChunkingEngine] 페이지 1/12 Vision 분석 중... (8.3%)
    페이지 1/12 처리 중...
  → 이미지 인코딩 중...
  → 이미지 인코딩 완료 (XXXXX bytes)
  → Vision API 호출 중... (모델: gpt-4o-mini)
  → API 요청 전송 중... (타임아웃: 연결 10초, 읽기 60초)
  → API 응답 수신 완료 (응답 시간: X.XXs)
[PDFChunkingEngine] ✓ 페이지 1/12 Vision 분석 완료 (XXX chars)
...
[PDFChunkingEngine] Vision 처리 완료: 12개 청크 생성
✅ 완료: test.pdf
```

**확인 사항**:
- ✅ 모든 페이지가 순서대로 처리됨
- ✅ "타임아웃: 연결 10초, 읽기 60초" 메시지 출력됨
- ✅ 진행 상황 실시간 업데이트
- ✅ 에러 없이 완료

---

### **시나리오 2: 업로드 취소 테스트**

**목적**: 사용자가 업로드 중 취소 버튼을 눌렀을 때 즉시 반응하는지 확인

**준비물**:
- 20페이지 이상의 PDF 파일 (취소 버튼을 누를 시간 확보)

**테스트 절차**:
1. 데스크톱 앱 실행
2. "문서 업로드" 탭 선택
3. 대용량 PDF 파일 업로드 시작
4. **페이지 4~5 처리 중에 "업로드 취소" 버튼 클릭**
5. 콘솔 출력 관찰

**예상 결과**:
```
[PDFChunkingEngine] 페이지 4/20 Vision 분석 중... (20.0%)
    페이지 4/20 처리 중...
  → 이미지 인코딩 중...
[사용자가 취소 버튼 클릭]
⚠️ 업로드 취소됨: large_file.pdf
```

**확인 사항**:
- ✅ 취소 버튼 클릭 후 즉시 중단됨 (1~2초 이내)
- ✅ "업로드 취소됨" 메시지 표시
- ✅ 시스템이 정상 상태로 복구됨 (다른 작업 가능)
- ✅ 부분 업로드된 데이터가 DB에 저장되지 않음

---

### **시나리오 3: 타임아웃 테스트 (네트워크 문제 시뮬레이션)**

**목적**: 네트워크 타임아웃이 70초 이내에 감지되는지 확인

**준비물**:
- PDF 파일 (아무거나)
- 네트워크 연결 제어 (Wi-Fi 끄기 등)

**테스트 절차**:
1. 데스크톱 앱 실행
2. "문서 업로드" 탭 선택
3. PDF 파일 업로드 시작
4. **첫 페이지 Vision API 호출 중에 Wi-Fi 끄기** (또는 네트워크 케이블 뽑기)
5. 타이머로 시간 측정
6. 콘솔 출력 관찰

**예상 결과** (재시도 3회 후 실패):
```
[PDFChunkingEngine] 페이지 1/12 Vision 분석 중... (8.3%)
  → Vision API 호출 중... (모델: gpt-4o-mini)
  → API 요청 전송 중... (타임아웃: 연결 10초, 읽기 60초)
  [재시도 1/3] 2초 후 재시도... (오류: Connection timeout)
  [재시도 2/3] 4초 후 재시도... (오류: Connection timeout)
  [재시도 3/3] 8초 후 재시도... (오류: Connection timeout)
[ERROR] 페이지 1 Vision 분석 실패 (재시도 3회 초과): Connection timeout
❌ 업로드 실패: test.pdf
   일부 페이지 처리 실패로 전체 업로드가 취소되었습니다.
   실패한 페이지: 1
```

**확인 사항**:
- ✅ 최대 대기 시간: 약 70초 + 재시도 대기(2+4+8=14초) = **약 84초** 이내
- ✅ 무한 대기 없음 (기존 문제 해결)
- ✅ 재시도 메시지 3회 출력
- ✅ "실패한 페이지: 1" 명시
- ✅ 시스템 정상 복구 (다른 질문 가능)

---

### **시나리오 4: 일시적 네트워크 불안정 - 재시도 성공**

**목적**: 재시도 로직이 정상 작동하여 일시적 오류를 복구하는지 확인

**준비물**:
- PDF 파일
- 네트워크 연결 제어

**테스트 절차**:
1. 데스크톱 앱 실행
2. PDF 파일 업로드 시작
3. **첫 페이지 Vision API 호출 중에 Wi-Fi 끄기**
4. **5초 후 Wi-Fi 다시 켜기** (재시도 중)
5. 콘솔 출력 관찰

**예상 결과** (재시도 성공):
```
[PDFChunkingEngine] 페이지 1/12 Vision 분석 중... (8.3%)
  → Vision API 호출 중... (모델: gpt-4o-mini)
  → API 요청 전송 중... (타임아웃: 연결 10초, 읽기 60초)
  [재시도 1/3] 2초 후 재시도... (오류: Connection timeout)
  [재시도 성공] Vision API 호출 성공
[PDFChunkingEngine] ✓ 페이지 1/12 Vision 분석 완료 (XXX chars)
[페이지 2 이후 정상 진행...]
✅ 완료: test.pdf
```

**확인 사항**:
- ✅ 재시도가 자동으로 수행됨
- ✅ 재시도 성공 시 정상 진행
- ✅ 전체 업로드 완료
- ✅ 사용자에게 명확한 피드백

---

### **시나리오 5: 페이지 4에서 실패 (원래 보고된 문제)**

**목적**: 원래 보고된 "페이지 4에서 중단" 문제가 해결되었는지 확인

**준비물**:
- 12페이지 PDF 파일

**테스트 절차**:
1. 데스크톱 앱 실행
2. 문제가 발생했던 동일한 PDF 파일 업로드
3. 콘솔 출력 관찰
4. 타이머로 시간 측정

**예상 결과 (문제 해결됨)**:
```
[PDFChunkingEngine] 페이지 1/12 Vision 분석 중... (8.3%)
[정상 처리]
[PDFChunkingEngine] 페이지 2/12 Vision 분석 중... (16.7%)
[정상 처리]
[PDFChunkingEngine] 페이지 3/12 Vision 분석 중... (25.0%)
[정상 처리]
[PDFChunkingEngine] 페이지 4/12 Vision 분석 중... (33.3%)
  → API 요청 전송 중... (타임아웃: 연결 10초, 읽기 60초)
[만약 네트워크 문제 발생 시]
  [재시도 1/3] 2초 후 재시도...
  [재시도 2/3] 4초 후 재시도...
  [재시도 성공] 또는 [재시도 3회 초과 → 명확한 에러 메시지]
```

**확인 사항**:
- ✅ 페이지 4에서 무한 대기하지 않음
- ✅ 70초(+재시도 14초) 이내 타임아웃 감지
- ✅ 명확한 에러 메시지 출력
- ✅ 취소 버튼 작동
- ✅ 시스템 복구 가능

---

### **시나리오 6: 재시도 중 취소**

**목적**: 재시도 대기 중에도 취소 버튼이 작동하는지 확인

**준비물**:
- PDF 파일
- 네트워크 연결 제어

**테스트 절차**:
1. PDF 파일 업로드 시작
2. **첫 페이지 Vision API 호출 중에 네트워크 끄기**
3. 재시도 메시지 출력 확인
4. **재시도 대기 중(2초, 4초, 8초)에 취소 버튼 클릭**
5. 콘솔 출력 관찰

**예상 결과**:
```
[PDFChunkingEngine] 페이지 1/12 Vision 분석 중... (8.3%)
  → API 요청 전송 중... (타임아웃: 연결 10초, 읽기 60초)
  [재시도 1/3] 2초 후 재시도... (오류: Connection timeout)
[사용자가 대기 중 취소 버튼 클릭]
⚠️ 업로드 취소됨: test.pdf
```

**확인 사항**:
- ✅ 재시도 대기 중에도 취소 즉시 반응
- ✅ "업로드 취소됨" 메시지 표시
- ✅ 시스템 정상 복구

## 🔍 추가 확인 사항

### 2. 에러 메시지 품질
- [ ] 실패 원인 명확히 표시 (Timeout, Connection Error, HTTP 429 등)
- [ ] 실패한 페이지 번호 표시

### 3. 시스템 안정성
- [ ] 에러 후에도 다른 질문 가능
- [ ] 에러 후에도 다른 파일 업로드 가능
- [ ] 메모리 누수 없음 (장시간 사용 시)

### 4. 부분 업로드 방지
- [ ] 실패 시 DB에 부분 데이터 저장되지 않음

## 💡 테스트 팁

1. **콘솔 출력 확인**: 모든 테스트는 콘솔 출력을 주의 깊게 관찰하세요

4. **네트워크 조건**: 안정적 네트워크와 불안정한 네트워크 모두 테스트하세요
