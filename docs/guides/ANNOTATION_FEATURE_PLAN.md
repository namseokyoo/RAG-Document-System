# Annotation(주석) 기능 개발 계획 (정확도 최우선)

**작성일**: 2026-01-12  
**대상 버전**: v0.7.3+  
**목표**: 문서(PDF/PPTX) 기반 RAG에 “사용자 코멘트/해석/결론”을 지속적으로 축적·검색·인용할 수 있는 Annotation 레이어 추가

---

## 1) 배경 및 문제 정의

논문/기술 결과(PPTX)의 핵심 정보는 표/그래프/수치(A)와 텍스트 설명(B), 그리고 비교/관계/원인(C)로 구성됩니다.  
하지만 조직에서 실제로 가치가 큰 정보(해석, 결론, 의사결정 맥락, 주의사항)는 문서 원문보다 **사람이 남기는 코멘트/정리 메시지**로 존재하는 경우가 많습니다.

Annotation 레이어는 다음을 해결합니다:
- 원문을 “팩트/근거”로 유지하면서
- 사람의 “해석/결론/리스크”를 동일한 질문 흐름에서 검색 가능한 근거로 제공

---

## 2) 요구사항(확정)

- **공식 기록/개인 의견을 분리하지 않고 하나의 Annotation으로 처리**
- **작성자(author)는 업로드 시 반드시 포함**
- 주석은 **페이지/슬라이드 귀속이 더 많음**(70%+)
- A/B/C 유형 질문 모두 지원
  - A는 “표 전체 요약(추세/비교)” 요구 비중이 큼
- PPTX는 이미지(차트/캡처)와 내장 표가 반반 수준 + 정리 메시지 존재

---

## 3) 핵심 설계 원칙(정확도 최우선)

### 3.1 원문 vs 주석의 역할 분리(답변 신뢰도 유지)
- **원문(Document chunks)**: 사실/수치/조건/측정 기준 등 “권위 있는 근거”
- **주석(Annotations)**: 해석/요약/결론/주의/리스크 등 “맥락 근거”

주석은 유용하지만, 특히 표/그래프(이미지) 해석에서 오판 가능성이 있으므로:
- 검색 리콜에는 적극 활용
- 최종 답변에서 가능한 한 **원문 근거(텍스트/표 구조)**로 교차 확인
- 원문과 충돌/불일치 시 “불확실/상충”을 표시하는 방향을 권장

### 3.2 검색 오염 방지(권장)
- “개인/공식 분리”는 하지 않더라도,
- 원문 컬렉션과 주석은 **별도 컬렉션으로 분리**하는 것을 권장  
  (원문 검색 결과가 주석에 의해 밀리는 오염 방지)

---

## 4) 데이터 모델(스키마)

### 4.1 Annotation Document (Vector DB 저장 단위)

#### 필수 필드
- `annotation_id`: UUID (불변)
- `author`: 문자열(필수) — 예: 사번/이메일/닉네임
- `created_at`, `updated_at`: ISO8601
- `file_name`: 원문 파일명(필수)
- `file_type`: pdf/pptx/…
- `page_number` 또는 `slide_number`: 앵커(가능하면 필수)
- `annotation_type`: summary / interpretation / decision / risk / issue / question / todo / observation 등
- `text`: 주석 본문

#### 권장 필드
- `visibility`: personal/team (컬렉션 분리 대신 필드로만 구분)
- `chunk_id`: 가능하면 연결 (정확도/출처 일관성에 큰 도움)
- `evidence_links`: 이 주석이 의존하는 원문 근거(페이지/청크) 리스트
- `tags`: 키워드(지표명, 조건, 소재 등)
- `confidence`: 작성자 신뢰도(0~1, 선택)
- `is_deleted`: soft delete
- `version`: 정수 증가 또는 `prev_id` 체인(선택)

### 4.2 임베딩 입력 텍스트 구성(권장)
- 자연어 본문만 넣지 말고, 앵커/타입/작성자를 함께 포함해 검색 정합성을 높임:
  - 예: `[ANNOTATION][type=decision][author=...][file=...][slide=12] ...`

## 5) Retrieval/합성 정책

### 5.1 기본 구조(2단 검색 + 합성)
1) 원문 검색 (기존 Hybrid/Rerank 파이프라인 유지)  
2) 주석 검색 (annotations 컬렉션)  
3) 질문 타입별 합성 규칙으로 컨텍스트 구성

### 5.2 질문 타입별 규칙(요약)
- **A(표/그래프/수치: “표 전체 요약”)**
  - 원문(표/텍스트/비전) 후보를 충분히 확보
  - 주석은 “요약/해석/결론”로 보조
  - 답변을 2단으로 구조화:
    1) 원문 기반 관측/수치/추세
    2) 주석 기반 해석/결론/주의 + (author, updated_at) 표시
- **B(요약/설명)**
  - 주석 비중 확대 가능(정리 메시지 활용)
  - 최소 1개 이상 원문 근거 유지
- **C(비교/관계/원인)**
  - 주석은 큰 가치(해석/원인 추정/실험 설계의 함정)
  - 앵커(페이지/슬라이드) 단위로 그룹핑해서 컨텍스트 구성

---

## 6) UI/UX 통합(권장 흐름)

- 답변의 “참고 문서(파일/페이지/슬라이드)” 항목에 주석 상태 표시:
  - 예: `📝 주석 3개`
- 클릭 시 해당 페이지/슬라이드의 주석 패널 열기(조회/추가/수정)
- 주석 작성 시 `file_name`, `page/slide` 자동 채움(오입력 최소화)
- 필수 입력: `author`, `annotation_type`, `text`

---

## 7) 개발 단계(권장)

### Phase 1: 최소 기능(MVP)
- annotations 컬렉션 추가(별도)
- 페이지/슬라이드 앵커 주석 CRUD + 작성자 필수
- 주석 검색(단독) + UI에서 주석 패널 제공

### Phase 2: RAG 통합(정확도 체감 구간)
- 질의 시 원문+주석 2단 검색 및 합성
- A 질문(표 전체 요약)에서 2단 답변 템플릿 적용(원문/주석 분리)

### Phase 3: 품질/운영 강화
- 충돌 감지(원문 vs 주석 상충) 및 표기
- 버전/감사 추적(선택)
- 필터링: author/visibility/annotation_type

---

## 8) 검증(평가) 제안

- 평가셋 60문항(권장): A 20 / B 20 / C 20
- 측정 지표:
  - annotation_hit_rate (주석이 실제 답변에 기여한 비율)
  - citation_mix (원문 근거 vs 주석 근거 비중)
  - conflict_rate (상충/불확실 표기 비율)
  - A 질문 만족도(“표 전체 요약”) — 체감 개선 핵심
