## 🎯 핵심 발견: ColPali 접근법

### 개념

**기존 RAG 파이프라인** (복잡함):
```
PDF → OCR → 레이아웃 분석 → 텍스트 추출 → 청킹 → 임베딩 → 검색
```

**ColPali 접근법** (단순함):
```
PDF → 페이지 이미지 → Vision 임베딩 → 검색
```

### 핵심 아이디어

1. **페이지 전체를 이미지로 직접 임베딩**
   - OCR, 파싱 불필요
   - 레이아웃 정보 보존
   - 표/차트/이미지 모두 포함

2. **Multi-vector Retrieval** (ColBERT 방식)
   - 페이지를 32x32 패치로 분할 (1024개 패치)
   - 각 패치마다 임베딩 벡터 생성
   - Late interaction: 쿼리와 패치별 매칭

3. **PaliGemma 기반 Vision Language Model**
   - Google의 최신 VLM
   - 문서 이해에 특화

### 장점

✅ **단순함**: OCR/파싱/레이아웃 분석 불필요
✅ **정확함**: 기존 방법 대비 성능 우수
✅ **빠름**: 인덱싱 속도 빠르고 쿼리 지연 낮음
✅ **범용성**: 모든 문서 타입 지원

### 단점

⚠️ **비용**: 페이지당 임베딩 비용 (텍스트보다 비쌈)
⚠️ **저장 공간**: Multi-vector → 1024배 공간
⚠️ **검색 속도**: 패치별 매칭 → 느릴 수 있음

## 💡 GPT-4V 베스트 프랙티스 (2024)

### 1. 프롬프트 엔지니어링이 핵심

**문제**: GPT-4V가 표를 잘못 추출
**해결**: 프롬프트 개선

**Before**:
```
"이 슬라이드를 분석하세요"
```

**After**:
```
"이 슬라이드의 표 제목은 '{제목}'입니다.
표만 추출하세요 (불릿 포인트 제외).
헤더와 푸터는 제외하세요."
```

**결과**: 정확도 대폭 향상 (특히 작은 모델에서)

### 2. 이미지 해상도 최적화

| 해상도 | 토큰 수 | 비용 | 품질 |
|--------|---------|------|------|
| **Low-res** | 85 tokens | $0.0001 | 대부분 충분 |
| High-res | 600 tokens | $0.0009 | 복잡한 표 필요 시 |

**권장**: 기본은 Low-res, 복잡한 표만 High-res

### 3. 구조화된 출력 강제

**문제**: 자유 형식 텍스트 → 파싱 어려움
**해결**: JSON 형식 강제

```python
prompt = """
슬라이드를 분석하여 JSON 형식으로 출력하세요:

{
  "title": "슬라이드 제목",
  "data_type": "표/그래프 형태",
  "numbers": [
    {"item": "항목명", "value": "값", "unit": "단위"}
  ],
  "trend": "증감 패턴"
}
"""
```

### 4. 슬라이드 제목 명시

**우리의 문제**: 슬라이드 3 내용이 슬라이드 4로 인식
**해결**: 슬라이드 제목을 프롬프트에 포함

```python
prompt = f"""
슬라이드 제목: "{slide_title}"

위 제목의 슬라이드를 분석하세요.
슬라이드 상단의 큰 제목과 일치하는지 확인하세요.
"""
```

## 📖 최신 논문 (2024)

### 1. Unified Multi-Modal Document Representation (Oct 2024)

**arXiv**: 2410.02729

**핵심**:
- 텍스트 + 이미지 + 표를 **통합 임베딩**으로 표현
- VLM으로 문서 페이지를 인터리브 방식으로 임베딩
- 단일 벡터로 검색 가능

**우리 시스템에 적용**:
- slide_summary 청크를 VLM 임베딩으로 대체
- 텍스트 임베딩 대신 Vision 임베딩 사용

### 2. Granite Vision (Feb 2025)

**arXiv**: 2502.09927

**핵심**:
- **표/차트 → 구조화된 형식 변환** SOTA
- 경량 모델이지만 성능 우수
- LiveXiv 벤치마크: 최신 arXiv 논문 이해

**우리 시스템에 적용**:
- 표 추출 시 JSON/Markdown 형식 강제
- 차트는 데이터 포인트로 변환

### 3. VisDoM (Dec 2024)

**arXiv**: 2412.10704

**핵심**:
- 다중 문서, 다중 모달 QA 데이터셋
- ColPali 사용: **OCR 없이** 문서 이미지 직접 임베딩
- 표/차트/슬라이드 포함

**우리 시스템에 적용**:
- ColPali 방식 도입 고려
- Multi-document RAG 확장

### 4. MMC: Chart Understanding (May 2024)

**arXiv**: 2311.10774

**핵심**:
- 차트 전용 대규모 데이터셋 (600K)
- 차트 QA 벤치마크 SOTA
- 차트 유형별 특화 프롬프트

**우리 시스템에 적용**:
- 차트 슬라이드 감지 시 차트 전용 프롬프트 사용
- 차트 유형별 (막대/선/파이) 맞춤 분석

## 🔧 우리 시스템 개선 방향

### 즉시 적용 가능 (프롬프트 강화)

#### 1. 슬라이드 제목 명시 (가장 중요!)

**현재**:
```python
prompt = """
슬라이드를 분석하여 다음 정보를 추출하세요:
1. 주제: 핵심 메시지 (1문장)
...
"""
```

**개선**:
```python
prompt = f"""
슬라이드 제목: "{slide_title}"

위 제목의 슬라이드를 분석하세요.
슬라이드 맨 위의 큰 제목이 "{slide_title}"과 일치하는지 확인하세요.
일치하지 않으면 오류를 보고하세요.

다음 정보를 추출하세요:
1. 주제: 슬라이드 제목 기반 핵심 메시지 (1문장)
...
"""
```

#### 2. 구조화된 출력 (JSON)

**현재**: 자유 형식 텍스트
```
주제: ...
데이터 유형: ...
```

**개선**: JSON 형식 강제
```json
{
  "slide_title_match": true,
  "topic": "...",
  "data_type": "...",
  "numbers": [...],
  "trend": "..."
}
```

#### 3. 표/차트 전용 프롬프트

**표 슬라이드**:
```
이 슬라이드는 표를 포함합니다.
표의 구조: {rows}행 x {cols}열
헤더: {headers}

표의 모든 숫자를 정확히 추출하세요.
```

**차트 슬라이드**:
```
이 슬라이드는 {chart_type} 차트를 포함합니다.
축 라벨: X축={x_label}, Y축={y_label}

차트의 데이터 포인트를 추출하세요.
```

### 중기 적용 가능 (아키텍처 개선)

#### Option A: ColPali 방식 도입

**개념**:
- 슬라이드 이미지 → Multi-vector 임베딩
- 텍스트 추출 불필요
- Vision 임베딩으로 검색

**장점**:
- 단순함 (파싱 불필요)
- 정확함 (레이아웃 보존)

**단점**:
- 비용 (패치당 임베딩)
- 저장 공간 (1024배)

**적용 시나리오**:
- 표/차트 슬라이드만 ColPali
- 텍스트 슬라이드는 기존 방식

#### Option B: Hybrid 접근법 (권장)

**표 슬라이드**:
1. python-pptx로 표 구조 추출 (무료, 정확)
2. Vision은 차트만 사용

**차트 슬라이드**:
1. Vision으로 차트 분석
2. 데이터 포인트 추출

**텍스트 슬라이드**:
1. Vision 건너뜀
2. 텍스트 추출만

**효과**:
- Vision 호출 70% 감소
- 표 정확도 99%
- 비용 70% 절감

#### Option C: Layout 분석 + 영역별 Vision

**개념**:
1. Layout Detection (표/차트/텍스트 영역 분리)
2. 각 영역별로 Vision 분석
3. 통합

**장점**:
- 정확도 향상 (집중 분석)
- 맥락 보존

**단점**:
- 복잡도 증가
- Layout Detection 필요

## 🎯 즉시 실행 계획

### 1. 프롬프트 강화 (오늘)

**변경 사항**:
```python
# Before (28라인)
"""
슬라이드를 분석하여 다음 정보를 구조화된 형식으로 추출하세요:
1. 주제: 핵심 메시지 (1문장)
...
"""

# After (35라인, 추가 7라인)
f"""
[슬라이드 정보]
제목: "{slide_title}"
위치: 슬라이드 {slide_num}/{total_slides}

[검증]
슬라이드 맨 위의 큰 제목이 "{slide_title}"과 일치하는지 확인하세요.
다른 슬라이드의 내용을 분석하지 마세요.

[분석 지시]
위 슬라이드만 분석하여 다음 정보를 추출하세요:

1. 주제: 슬라이드 제목({slide_title}) 기반 핵심 메시지 (1문장)
2. 데이터 유형: 표/그래프 형태
   - 표: "{rows}행 {cols}열" 형식으로 명시
   - 그래프: "막대/선/파이 그래프" 유형 명시
3. 주요 수치: 모든 숫자를 "항목명: 값 (단위)" 형식으로
4. 비교/추이: 증감률, 변화 패턴

[출력 형식]
주제: [슬라이드 제목 기반 메시지]
데이터 유형: [표/그래프 상세]
주요 수치:
- [항목1]: [값1]
- [항목2]: [값2]
비교/추이: [...]

[주의]
- 슬라이드 제목과 일치하지 않는 내용은 오류 보고
- 다른 슬라이드 내용 혼동 금지
"""
```

**예상 효과**:
- 슬라이드 혼동 문제 **80% 해결**
- 주제 파악 정확도 **90%** 달성
- 토큰 증가: 103 → 120 tokens (17% 증가, 허용 범위)

### 2. 테스트 (내일)

**검증 항목**:
- [ ] 슬라이드 3 혼동 문제 해결 확인
- [ ] 표 숫자 정확도 유지 (100%)
- [ ] 주제 파악 정확도 측정
- [ ] 비용 증가 확인 (17% 예상)

## 🔑 핵심 메시지

### 현재 문제의 본질

**슬라이드 혼동**은 **프롬프트 부족**이 원인:
- 슬라이드 제목 정보 없음
- 검증 메커니즘 없음
- 맥락 정보 부족

### 해결책

**즉시**: 프롬프트 강화 (슬라이드 제목 명시)
**단기**: Smart Vision Decision (표는 직접 추출)
**중기**: ColPali 방식 (이미지 직접 임베딩)

### 멀티모달 RAG의 미래

**ColPali가 제시한 방향**:
- OCR/파싱 불필요
- 페이지 이미지 직접 임베딩
- Multi-vector retrieval

**우리 시스템 적용**:
- 표: 직접 추출 (python-pptx)
- 차트: Vision 분석 (GPT-4V)
- Hybrid: 텍스트 + Vision 임베딩

**확장 가능성**:
- PPT → PDF
- 표/차트 → 이미지/다이어그램
- 단일 문서 → 다중 문서
