perf: Optimize settings save with smart updates and loading indicator

## Problem
Settings save caused UI freeze (응답없음) especially with slow network:
- Always called update_embeddings() even when unchanged (~2s + API call)
- Always called update_llm() even when unchanged (~0.5s)
- Always called reconnect_shared_db() even when path unchanged (10-30s on slow network)
- No progress feedback - users didn't know it was working

## Solution 1: Smart Update (Only Update What Changed)
Track old vs new values and only call update methods when changed:
- Embedding changed? → update_embeddings()
- LLM changed? → update_llm()
- Multi-query changed? → update multi_query settings
- Retriever changed? → update_retriever()
- Shared DB path changed? → reconnect_shared_db()

## Solution 2: Loading Indicator
Added QProgressDialog with status messages:
- "설정 적용 중..." (generic)
- "임베딩 설정 적용 중..." (embedding update)
- "LLM 설정 적용 중..." (LLM update)
- "검색 설정 적용 중..." (retriever update)
- "공유 DB 연결 중..." (shared DB reconnect)

## Performance Impact
Before: Always 2-30+ seconds (depending on network)
After:
- No changes: <0.1s (instant - only saves config.json)
- LLM only: ~0.5s
- Embedding only: ~2s
- Shared DB only: 2-15s (network dependent)

Users now see progress and can tell the app is working.
